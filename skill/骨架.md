# 骨架｜Listing 输出结构（8 类目通用）

> 这份文件只管「长什么样」，「什么不能写」在 `rules-mx.md` / `rules-br.md` + `类目/` 里，
> 「凭什么让人买」在 `转化层.md` 里。三层都要过，缺一层就是残品。
> 底本：Gemini V3.2 的排版规范与输出结构，去掉短视频脚本模块后的版本。

---

## 1. 硬规范

- 语言：100% 站点语言（MX = es-MX，BR = pt-BR）。**禁止中文、禁止英文混排、禁止西葡混用**
- 纯文本，可直接粘进后台（**不带任何 Markdown 标记**，加粗由运营在后台手动设置）
- **不输出前言、不解释思路、不加引用标记**
- **禁止结构标签**：不要出现 `标题：`、`Gancho:`、`Características:`、`卖点1` 这类提示词
- 缺失参数写 `[POR CONFIRMAR]`；中文原因写在审核备注里，不进正文

## 2. 标题

| 项 | 规则 |
|---|---|
| 长度 | 默认 60–80 字符（移动端建议，**不是平台上限**：MX 300 / BR 200）；汽摩配 80–120；超 80 时前 40 字符必须已表达完整卖点 |
| 卡位 | 核心搜索词必须落在前 30 字符内（防手机端截断） |
| 结构 | `核心词 + 关键规格 + 用途词 \| 次卖点 + 品牌（句尾）` |
| 关键词三层 | L1 品类词（前 30）+ L2 用途词（`para …`）+ L3 修饰词（材质/规格/数量，**只放一个**）。详见 `转化层.md` §1 |
| 点击率 | 前 30 字符要能独立成立：买家只看这三个词就知道这是什么、给谁用 |
| 用途词 | **必带**（para carro / para madera / para uñas…）；只写品类词会丢掉一半搜索 |
| 核心词覆盖 | 原平台核心词的**每个实词**都要出现在标题里（ML 核心词一般不带重音，比对时忽略重音；"de/la/y" 这类虚词不算） |
| 品牌 | 自有且有认知 → 放句尾，不删；无授权品牌名 → 禁止 |
| 分隔符 | `\|` 可用（V3.2 九条案例实测有效）；若平台判为特殊符号，降级用 `-` |
| 禁止 | Emoji、整段全大写、促销词、价格、包邮承诺、无授权品牌名、尺寸/颜色（汽配左右前后除外） |

## 3. 描述骨架

```text
¿钩子: 一个痛点或场景?                          ← 西语用 ¿...? / ¡...!；葡语无倒标点。冒号用半角 :
                                                ← 空行
⭐ 卖点1 短语: 一句解释（先讲利益）
⭐ 卖点2 短语: 一句解释
⭐ 卖点3 短语: 一句解释
⭐ 卖点4 短语: 一句解释（低客单价加连带销售暗示）
                                                ← 空行
📋 Especificaciones Técnicas: / 📋 Especificações Técnicas:
- 参数: 值 + 单位
- 参数: 值 + 单位
                                                ← 空行
📦 Contenido del Paquete: / 📦 Conteúdo da Embalagem:
- 主体 x数量
- 配件清单
- 电池/耗材不含时写 NO incluidas / NÃO inclusas（写在正文里，不加粗）
                                                ← 空行
💡 Preguntas Frecuentes (FAQ): / 💡 Perguntas Frequentes (FAQ):
- 问题? 回答。
- 问题? 回答。
                                                ← 空行
CTA（Compra segura / Compra com proteção）
#标签（默认关闭，A/B 后再定）
```

排版细则：

- **正文是纯文本，禁用 Markdown**：不写 `**加粗**`、`__`、`#`、`|` 表格。TikTok 后台是富文本编辑器，不解析 Markdown，`**` 会原样显示成星号。卖点短语的加粗由运营粘进后台后**手动选中加粗**
- **标点用半角**：`: ; , ( )`；中文全角标点 `：，。（）` 一律不出现（描述里出现 `：` 就是要报错的信号）
- 段落最多 2–3 行，必须空行隔开
- **卖点（⭐ 行）之间必须空一行**：后台预览会把连续行合并成一段“文字墙”，空行才能让每条独立成行
- 每条卖点单行 Emoji ≤ 2 个
- 规格、清单用 `-` 引导，不用表格、不用序号
- 卖点 3–5 条；少于 3 条说明事实不够，先补资料

**首屏两行（折叠可见区，决定留不留）**：

- 第 1 行（钩子）必须是**具体场景/痛点**，≤ 60 字符；禁止 `alta calidad` / `excelente` / `perfecto para` / `ideal para` 这类空泛开场
- 第 2 行起第一条卖点 = **最痛的那个利益**，不许以参数开头（参数进规格区）
- 卖点按决策权重排：痛点 → 兼容 → 材质耐用 → 易用 → 连带
- 详见 `转化层.md` §3 §4

## 4. 模块开关

| 模块 | 默认 | 说明 |
|---|---|---|
| A. 商品 Listing | **必出** | 标题 + 描述 |
| B. 短视频脚本 | **默认关闭** | 只在明确提出时生成；默认输出会翻倍消耗额度 |
| C. 中文审核备注 | 精简一行 | 只写：缺哪些参数、核心词是什么 |

## 5. 输出前自检（模型自检，脚本还会再跑一遍）

### 5.1 合规自检（8 条，任一不过即重写）

1. 全文是否只有站点语言？有无中文残留？
2. 标题是否在长度区间、核心词是否在前 30 字符？
3. 每个硬参数是否都能在输入资料里找到出处？（找不到就改 `[POR CONFIRMAR]`）
4. 有没有出现禁词、`Compra protegida`、自造包邮、站外导流？
5. `100%` 是否只用在材质成分上？
6. 卖点是不是 3–5 条、每条一行？正文有没有 `**` 或全角标点残留？
7. 包装清单是否列了"不含电池"？
8. 有没有 `标题：` 这类结构标签或引用标记？

### 5.2 转化自检（6 条，脚本报 P2-转化）

1. 标题前 30 字符是否含 **L1 品类词 + L2 用途词（para…）**？
2. 描述第 1 行是不是**具体场景/痛点**（不是形容词、不是空泛开场）？
3. 第一条卖点是不是最痛的利益（不是参数）？
4. 卖点是否 **3–5 条**、按决策权重排？
5. 类目 3 个高频疑虑是否都回答（兼容 / 清单 / 隐藏成本）？FAQ 是否 ≥ 2 条？
6. 写的每项权益后台是否**真实存在**？

> 5.1 管「能不能上架」，5.2 管「卖不卖得动」。只过 5.1 的 Listing 是合格废品。
