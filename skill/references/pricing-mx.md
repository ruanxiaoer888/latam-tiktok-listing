# 墨西哥站定价决策框架（存档备用）

> **来源**：`codex-skill/references/pricing-mexico.md`（英文原版）的中文适配版。
> **维护注意**：修改定价规则时需同步更新 codex-skill 和 skill 两处，避免规则漂移。

> **当前状态**：存档参考，未集成进生成流程。当需要做半自动定价时启用。

## 适用场景

- 用户明确要求定价建议
- 批量生成时需要填充价格字段
- 促销活动策划

常规 Listing 生成不涉及定价，价格由运营在后台手动填写。

## 价格角色识别（先定性再定量）

在给任何数字之前，先判断手里有什么：

| 角色 | 定义 | 处理 |
|---|---|---|
| **店铺价** | 用户已设定的 TikTok Shop 售价 | 保留，不替换；有矛盾只提醒 |
| **参考零售价** | 美客多/其他平台的实际成交价 | 可作为测试价锚点，必须注明来源和采集日期 |
| **采购成本** | 进货价 + 落地成本 | 仅作为成本输入，不得直接当零售价 |
| **条件性金额** | 分期价、券后价、运费补贴 | 与无条件零售价分开标注 |

角色不明确时标 `[POR CONFIRMAR]`，不猜测。

## 默认推荐逻辑

当需要推荐价格、且没有店铺价可保留时：

1. 有可比参考零售价（同币种、同变体、有采集日期）→ 以该价格为测试价推荐，标注 `市场锚定测试价 / precio de prueba anclado al mercado`
2. 无合理调整理由 → 不做固定百分比加价，保留参考价原值
3. 尾数调整（x9/x99）→ 仅在有商业理由时改，不作为默认规则
4. 无足够依据 → 标 `[POR CONFIRMAR]`，不编价格

**禁止**：把采购成本加一个拍脑袋的倍率当作推荐价。

## 成本感知计算（仅在用户请求详细分析时使用）

变量定义：
- `C` = 落地产品成本 + 固定履约/运费/退货预留
- `r` = 平台佣金率（按售价基数）
- `P` = 售价
- `m` = 目标贡献利润率（用户指定）

公式：
- 盈亏平衡价 = `C / (1 - r)`
- 目标利润价 = `C / (1 - r - m)`
- 在售价 P 下的贡献利润 = `P × (1 - r) - C`
- 在售价 P 下的贡献利润率 = 贡献利润 / P

约束检查：
- `1 - r > 0` 才能算盈亏平衡
- `1 - r - m > 0` 才能算目标利润价
- 分母 ≤ 0 时停止该计算，标输入缺失

**注意**：盈亏平衡只覆盖已纳入的成本，不代表整体业务盈利。

## 促销决策树（仅在用户请求促销方案时使用）

| 目标 | 推荐类型 | 前提 |
|---|---|---|
| 短期流量/转化冲刺 | Oferta relámpago（秒杀） | 可限制时长/数量，价格在成本可承受范围内 |
| 拉新首单 | Cupón para nuevos clientes（新人券） | 门槛金额合理，不会逼买家凑单买不需要的东西 |
| 成本/资格信息不全 | 条件性示例 | 标 `[POR CONFIRMAR]`，列缺失项，不称"利润安全" |

促销资金来源必须明确标注：`seller-funded` / `platform-funded` / `shared`。未知时标待确认。

买家支付金额 ≠ 卖家收入。不得从买家折扣反推卖家到手。

## 输出规范

- SKU 表里只放：保留的店铺价 / 有依据的推荐价 / 待确认标记
- 推荐价附简短依据（来源+日期 或 成本基础）
- 不单独出定价报告，除非用户明确要求
- 促销方案只在被请求时出现，不随常规 Listing 自动生成

## 与本 pipeline 的集成点

- 价格字段不进 Listing 正文（`rules-mx.md` 硬约束）
- 价格出现在 SKU 表 / 上架信息.md 里
- 推荐价必须标注为「建议」，不得暗示已验证利润
- 所有价格计算基于 `facts.json` 里的数据，不从原始描述取

## 启用条件

当以下任一条件满足时，从存档转为活跃：
1. 用户在 AGENTS.md 或对话中明确要求自动定价
2. 批次生成模板里新增了价格必填字段
3. 建立了稳定的成本数据源（ERP 对接完成）

启用前需更新本文件顶部的「当前状态」。
