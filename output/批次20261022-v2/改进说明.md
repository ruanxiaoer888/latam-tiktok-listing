## 一、改了什么（三层）

### 1. 数据层：给每个 SKU 抽「场景卡」（新增 `qa\build_scene.py`）

旧流程只让 Agent 读 `facts.json`，里面只有参数，没有「用在哪、什么痛点、和普通款差在哪」，所以钩子只能编，81 条里 81 条都是 `¿…?` 模板问句。

新增 `build_scene.py`：从美客多原始描述里**抽取**（不推断、不翻译、不新增）：

- 场景与用途（`Usos recomendados` / `Escenarios de aplicación` / `Apto para`）
- 卖点与差异化（原文编号特性，取首句）
- 原文规格（只作核对，正文以 facts 为准）
- 原文包装清单（用来发现 facts 解析截断）
- 使用/安全提示（进 FAQ）

产物：`output\_batch\scene\<SKU>.md`（108 份）。覆盖率：场景 87/108、卖点 103/108、包装 55/108。

### 2. 规范层：`_BRIEF.md`（本批新写，可直接给下一批复用）

在旧规则上加了几条硬要求：

- 标题：`para` 用途词尽量进前 30 字符；核心词片段写全；一个可验证规格
- 首屏钩子 ≤60 字符；**同一执行者问句不超过 60%**（避免全店一个腔调）
- 卖点 4–5 条：第一条讲利益不讲参数；**第 4 条必须写差异化**；**至少一条「决策信息」**（哪种砂纸用于哪步、含不含耗材、要不要另买）
- FAQ 固定 3 条：兼容/场景 → 含什么/怎么用 → 隐藏成本
- 参数：facts 优先；facts 没有而原文有明确数值的可写；电压一律 facts；没出处不写
- 新增 3 个金标准样例（AMU0000003 / ATVMX09400 / MBU6000001）

### 3. 执行层：5 个执行者并行（每人 15–16 条），统一 BRIEF

## 三、前后对照（两例）

### 例 1：AMU0000003 电动砂光机

**旧版**

```
Lijadora Orbital Eléctrica 125 mm 650 W 127V para Madera | Merion

¿La lija se despega y el polvo arruina el acabado?
```

**新版**

```
Lijadora Orbital Eléctrica para Madera 650 W | 125 mm Merion

¿Lijas la mesa y el polvo termina en toda la casa?

… ⭐ **16 lijas de 5 granos incluidas**：P60 para desbastar, P240 para alisar
   y P1000 para pulir; eliges según la superficie.
… ⭐ **También pule**：rueda de lana y plato de esponja incluidos…
```

差别：钩子从「抽象失败」变成「具体场景」；加了「哪种砂纸用在哪一步」的决策信息；卖点 4 → 5。

### 例 2：25011401 2 吨卧式千斤顶

**旧版**

```
¿Tu gato viejo no levanta el auto y te deja a pie?

⭐ **Cambia la llanta sin improvisar con tablas**：el gato levanta el auto desde el piso.
```

**新版**

```
¿Cambiar la llanta de noche sin un gato adecuado?

⭐ **Levanta el auto sin cargarlo a pulso**：el patín de 13.5 cm entra bajo el
   chasis y la palanca de 38 cm hace la fuerza por ti.
⭐ **Sube desde el lateral, no por el centro**：acerca el plato al refuerzo del
   chasis y reparte el peso; así trabajas con el auto estable.
```

差别：旧版只说「能顶起来」，新版说「怎么顶、顶哪、为什么稳」——这就是「帮客户做决策」。
