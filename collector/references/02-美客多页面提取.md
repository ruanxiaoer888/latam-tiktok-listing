# 02 美客多页面提取（数据在哪、怎么取、映射到哪些字段）

## 硬前提：必须在 `mercadolibre.com.mx` 页面上下文里取数

商品页数据只能**同源**读取（要在页面里带 cookie 发起请求），因此：

- `ml_extract.js` 必须通过 `dumate-browser-cli` 在当前已是美客多的页面上执行；
  `ml_batch.py` 会先 `goto https://www.mercadolibre.com.mx/` 再执行，就是这个原因
- 用 Python/curl 直接抓，或换域名/换站的上下文执行，都会被 CORS 或登录态校验挡下

## 数据入口：`__NORDIC_RENDERING_CTX__`

商品页（React SSR）把整份首屏状态塞在页面 HTML 的这段脚本里。取法：

1. 在 HTML 里 `indexOf("__NORDIC_RENDERING_CTX__")`，再按**花括号配平**（跳过字符串内的 `{}`）
   截出完整的 JSON 字面量，`JSON.parse` 得到 `root`
2. 状态主体在 `root.appProps.pageProps.initialState`（下面简称 `is`）

`ml_extract.js`（item 级，用 fetch 拿 HTML 再解析）和 `catalog_extract.js`（目录级，读当前
DOM 的 `document.documentElement.outerHTML`）用同一套 `parseNordic`，行为一致。

## 字段路径表（`is.components` 下的业务块）

| 目标 | 路径 | 说明 |
|---|---|---|
| 标题 | `components.header.title`（兜底 `components.title`） | |
| 副标题 | `components.header.subtitle` | |
| 评论 | `components.header.reviews` | 结构随页面版本变化，原样存 |
| 价格 | `components.price.price.value` / `.currency_symbol` / `.currency_id` / `.original_value` | 停售/目录页可能为空 |
| 价格状态 | `components.price.state` | 目录级页面的 `availability` 取自这里 |
| 库存/状态文案 | `components.item_status_message.body.text` | 如 `Publicación pausada` |
| 商品 ID | `is.id` | `MLM+数字` = item 级；空或 `MLMU...` = 目录级 |
| 规范链接 | `is.metadata.url_canonical` | |
| 描述标题/正文 | `components.description.title` / `.content` | 西语原文，**不翻译、不截断** |
| 卖家块 | `components.seller_data` | 序列化后截断 4000 字存入 `item.json.seller_data` |

埋点事件（`category_id` / `category_path` / `item_status` / `item_condition` / `listing_type_id` / `seller_id`）：

```
is.track.melidata_event.event_data
```

店铺名（`store_id` 取值）：`seller_data` 里没有现成的顶层字段，用正则从序列化文本里抠：

```
"shop_name"\s*:\s*"([^"]+)"
```

实测各店铺标签形态不一（如 `ATVERCE`、`BARNEYMX`、`MXMERION`、`CNMERION-MXF2`），所以
`store_id` 存页面原值，不做归一化；首批 15 个 SKU 的 `store_id` 是早前的人工映射，形态不同属正常。

## 图片

`components.gallery`：

- `pictures[]`：每张含 `id` / `sanitized_title` / `alt` / `width` / `height`
- `picture_config.template_zoom`：**最高分辨率原图**模板
- `picture_config.template_variants[]`：按宽度给的模板（脚本取 `width === "800"` 和 `"1200"`）
- `picture_config.template_thumbnail`：缩略图模板

模板是占位符字符串，把 `{id}` 和 `{sanitizedTitle}` 替换进图片对象即得 URL：

```
https  ://http2.mlstatic.com/D_NQ_NP_{id}-OO{sanitizedTitle}.jpg     ← url_original（-OO）
```

落盘时：

- **只用 `url_original`**（最高分辨率原图），保留原始格式与尺寸
- 文件名从 `01.jpg` 开始两位顺序编号，顺序与页面 `pictures[]` 一致
- 下载走 `build_input.py`（`urllib` + UA/Referer 头），失败重试 3 次，失败项记进
  `item.json.images[].error`；需要代理时加 `--proxy 127.0.0.1:7890`

## 规格属性（最容易踩坑的地方）

同一商品的规格块可能出现在两个组件里，**两处都要收，再按分组名/键值去重**：

| 组件 | 形态 | 采集方式 |
|---|---|---|
| `components.highlighted_specs_attrs` | 树 | 递归找 `type == "technical_specifications"` 的节点（`specs[]` 分组）与 `type == "key_value"` 的节点 |
| `components.highlighted_specs_attrs_swap` | 树 | 同上（部分是「高亮卖点」形态，才是真实属性） |

- `technical_specifications` → `{group, attributes:[{name, value}]}` 存入 `spec_groups`
- `key_value` → `{key, value}` 存入 `highlighted_kv`
- 去重：分组按 `group` 名，键值按 `key + \u0000 + value`
- 拍平表 `attributes_raw`：遍历 `spec_groups`，同名属性保留**首个**出现的值
- 用 `spec_source` 记录每个组件各贡献了多少分组/键值，方便事后核对为什么条数不等

## 批量抓取（`ml_batch.py` 的行为）

1. 在页面里设 `window.__URLS = [{sku, url}, ...]`（单批 ≤ 24 个）
2. 执行 `ml_extract.js`：对每个 URL 同源 `fetch(credentials:"include")`，逐条解析；一条失败不影响其它条
3. 结果返回 `btoa(JSON)`；`ml_batch.py` 合并成 `<work>/raw_<tag>.json`
4. 批间**串行 + 停顿**（默认 3 秒），不要并发——并发是最快触发风控的方式

每条记录里会带这些**判定信号**，供 `build_input.py` 判性质（不要在抓取阶段重试）：

| 字段 | 含义 |
|---|---|
| `blocked = "wall"` | 命中了验证码墙 / `account-verification` / 解析不出 nordic 数据 |
| `blocked = "404"` | HTTP 404 |
| `blocked = "delisted"` | 被重定向到 `/listado` 类目浏览页（`#redirectedFromVip`） |
| `blocked = "empty"` | 能拿到页面但没标题（壳页） |
| `data_level = "catalog"` | `is.id` 为空或以 `MLMU` 开头，即目录级页面 |
| `error` | 其它异常原文 |

## 目录级页面（原 item 停售时的重定向落点）

原 item 被卖家停售后，ML 把链接重定向到**同一商品的目录产品页**（URL 形如
`.../xxx/up/MLMUxxxx?pdp_filters=item_id:MLMxxxx`），页面提示
`Este producto no está disponible`。这种页面 fetch 拿不稳，必须 `goto` 到该 URL 后读 DOM：

```bash
python scripts/ml_catalog.py --items <work>\catalog_items.json --work <work>
```

采到的记录固定 `data_level: "catalog"`、`availability: "OutOfStock"`，价格与卖家为 `null`，
标题／描述／规格属性／全部原图照常采。落盘时 `input.json`／`item.json` 会同步标注并附 `note`。
