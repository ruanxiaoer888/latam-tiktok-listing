# 01 飞书表读取（拿到本次采集的权威清单）

采集的起点是飞书多维表格里的「商品链接」列。**只读，不写回飞书。**

## 前置

- 浏览器里**已登录飞书**（未登录会拿到 `ERR:no_table`）
- 浏览器通道可用（`dumate-browser-cli --version` 能出结果；`init` 成功）

## 怎么做

```bash
python scripts/read_sheet.py --work <工作区>\collector\_work
# 换表时显式传：
python scripts/read_sheet.py --url "https://xxx.feishu.cn/base/<app_token>?table=<table>&view=<view>"
```

脚本做三件事：`init` → `goto` 表 URL → 在当前页面执行 `scripts/feishu_read.js`，把结果写成
`<work>/_sheet_rows.json`。

## 页面内取数用的接口（`feishu_read.js` 里已封装）

```
GET /space/api/v1/bitable/<app_token>/clientvars
      ?tableID=<table>&viewID=<view>&recordLimit=500
      &needBase=true&viewLazyLoad=true&ondemandVer=2&openType=0
      (credentials: include —— 复用浏览器登录态)
```

要点：

- 返回的 `data.table` 是 **base64 的 gzip 数据块**，必须解压后才可读
  （页面里用 `atob` → `Uint8Array` → `DecompressionStream("gzip")` → `JSON.parse`）
- 解出来的对象里，`fieldMap` 是 `列id → {name}`，`recordMap` 是 `记录id → {单元格}`；
  脚本先按**列名**反查列 id，再取值。列名对不上时 `missing_fields` 会列出来
- 单元格值形态不一（字符串 / 数组 / 富文本对象），脚本里的 `toText()` 统一拍平成文本，
  数组用 ` | ` 连接
- 返回给 Python 的是 `B64:<base64(JSON)>`，`bridge.pick_b64()` 负责挑出并解码

## 产出结构（`_sheet_rows.json`）

```json
{
  "app_token": "...", "table": "...", "view": "...",
  "fieldMap": {"列id": "列名"},
  "missing_fields": [],
  "recordCount": 111,
  "with_link": 111,
  "rows": [
    {"rid": "...", "sku": "AMU0000005",
     "link": "https://articulo.mercadolibre.com.mx/MLM-...",
     "ml_title": "...", "item_id": "MLM...", "price": "...", "note": ""}
  ]
}
```

- `rows` 按 `sku` 升序
- **只有 `link` 非空的行才会被采**；有 SKU 无链接的行会打印出来提醒（这类行通常待补链接）
- 这份 JSON 是本次采集的**权威清单**：`gen_manifest.py` 用它算「待采／未采到」，清单也引用它的总数

## 排错

| 现象 | 原因 | 处理 |
|---|---|---|
| `ERR:no_table ...` | 当前页面没登录飞书，或 table/view id 改过 | 在浏览器里登录飞书后重跑 |
| `missing_fields` 非空 | 列被改名 | 改 `feishu_read.js` 里的列名常量 |
| `with_link` 远小于 `recordCount` | 表里有行没填链接 | 看脚本打印的「无链接的行」列表，去表里补齐 |
| `记录数` 比预期少 | `recordLimit` 不够 | `window.__FEISHU = {recordLimit: 1000}` 后重跑 |
