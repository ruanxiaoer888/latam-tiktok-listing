# 04 产物与命名规范（下游 `latam-tiktok-listing` 直接吃这份结构）

## 目录树

```
<input-root>\
├─ README.md                  （下游仓库自带，说明 input.json 必填字段）
├─ <SKU>\                     一个商品一个目录，目录名 = 飞书表「Tiktok商品SKU」原值
│  ├─ input.json              管道入参（下游 build_facts.py 从这里取）
│  ├─ item.json               完整采集明细（含图片清单与尺寸、卖家、状态）
│  ├─ img\                    商品原图
│  │  ├─ 01.jpg
│  │  ├─ 02.jpg
│  │  └─ ...
│  └─ overrides.json          （可选，人工修正项；下游优先读它）
└─ _<任何名字>\               `_` 开头 = 中间产物，采集与下游都跳过
```

- **不要**写 `description.json`（描述已进 `input.json.description_raw` / `item.json.description`）
- `facts.json` **不是**本流程产出——由下游 `qa\build_facts.py` 生成，是 Listing 的唯一事实来源

## 命名规则

| 对象 | 规则 |
|---|---|
| SKU 目录名 | 原样用飞书「Tiktok商品SKU」值（含数字、字母、`-`、`K` 后缀等，不改造） |
| 图片文件名 | `01.jpg` 起两位顺序编号，顺序与页面图片顺序一致；**保留原始格式与尺寸**，不转码不缩放 |
| 交付压缩包 | `ml-listing-input-<N>sku.zip`（N = 实际 SKU 目录数） |
| 采集清单 | 仓库根 `采集清单.md` |
| 中间产物 | `<仓库>\collector\_work\`（`raw_*.json`、`_sheet_rows.json`、`build_report.json`、`pending.json`） |

## `input.json` 字段（必填 9 项，少一个下游就断链）

| 字段 | 来源 | 说明 |
|---|---|---|
| `product_id` | SKU | 与目录名一致 |
| `source` | 固定 | `"mercadolibre"` |
| `source_url` | 页面解析后 URL | 首选 `resolved_url`（重定向后的真实地址） |
| `site` | 固定 | `"MX"` |
| `category` | 自动判定 | 中文类目（脚本内规则），可事后核对 |
| `title_raw` | 页面标题 | 西语原文，不改写 |
| `description_raw` | 页面描述正文 | 西语原文，**不翻译、不截断** |
| `price_source` | `{"currency":"MXN","amount":<数字或 null>}` | 停售/目录级为 `null` |
| `attributes_raw` | 拍平后的规格属性 | `{属性名: 值}` |
| `images` | `["./img/01.jpg", ...]` | 与 `img\` 下实际文件一一对应 |
| `variations` | 数组 | 当前恒为 `[]`（若有变体再补） |
| `store_id` | 页面 `shop_name` | 停售/目录级为空字符串 `""` |
| `core_keyword` | 自动判定 | 西语核心词，供下游生成标题用 |

目录级（原 item 停售）的 SKU **额外**带三个字段：

| 字段 | 值 |
|---|---|
| `data_level` | `"catalog"` |
| `availability` | `"OutOfStock"` |
| `catalog_product_id` | 目录产品 ID（如 `MLMU3773518725`） |
| `note` | 停售说明（中文，供人看） |

## `item.json` 结构（完整明细，下游主要读它）

| 顶层键 | 内容 |
|---|---|
| `sku` / `item_id` / `site` / `source` / `source_url` / `canonical_url` | 标识与链接 |
| `title` / `subtitle` / `reviews` | 标题区 |
| `price` | `{value, currency_symbol, currency_id, original_value}` 或 `null` |
| `category` | `{bucket_zh, ml_category_id, ml_category_path, ml_breadcrumb}` |
| `attributes` | `{groups:[{group,attributes:[{name,value}]}], flat:{}, highlighted:[{key,value}]}` |
| `description` | `{title, text, char_count}` |
| `images` | `[{index, file:"./img/01.jpg", url_original, page_width, page_height, bytes, format, width, height}]`（下载失败项含 `error`） |
| `seller_id` / `shop_name` / `seller_data` | 卖家侧（`seller_data` 为序列化后截断 4000 字） |
| `item_status` / `item_condition` / `listing_type_id` / `status_message` | 商品状态（常见 `Publicación pausada`） |
| `core_keyword` / `store_id` / `collected_at` | 判定项与采集日期 `YYYY-MM-DD` |

目录级记录同样追加 `data_level` / `availability` / `catalog_product_id` / `note`。

## 采集铁律（违反即不交付）

- **已采目录默认不覆盖**：`<SKU>\input.json` 已存在就跳过（增量采集的底线）；
  只有显式 `--force` 才重建，且重建前必须确认
- **`_` 开头目录一律跳过**（采集、清单、打包三处都要跳过）
- **描述保留西语原文**，图片保留原始格式与尺寸
- **清单必须与实际目录一致**：`gen_manifest.py` 只统计 `input\` 下真实存在的目录，
  不拿抓取日志充数；「未采到」表来自 `build_report.json` 的失败记录
- **校验不通过不交付**：`pack_and_verify.py` 会**直接验包内**内容——必填字段、图片数量与可读性、
  标题/描述非空；有 `must` 级问题就以非 0 退出，修完再跑

## 与 git / 搬机器的关系

- 图片与原始数据（`input/*/img/`、`input/*/input.json`、`input/*/item.json`）**不进 git**，
  用 U 盘 / 网盘搬运；仓库里保留的是 `input/README.md`（结构与字段说明）
- 中间目录 `collector/_work/` 建议加进 `.gitignore`
- 换机步骤见仓库根的 `迁移到新电脑.md`；下游技能本体用 `sync-to-skill.ps1` 同步到
  `%USERPROFILE%\.agents\skills\latam-tiktok-listing`
