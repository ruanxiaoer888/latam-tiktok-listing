# 03 风控与失效排查（采不到时按这里判，不要盲目重试）

## 一、验证码墙（最常见，且**不是**重试能解决的）

### 现象

- 商品页被重定向到 `.../captcha/wall/logged` 或 `.../gz/account-verification`
- 页面出现「安全验证 / 正在验证你」的拦截页
- 人工去点「Continuar」也点不动——**验证控件根本不渲染**

### 根因（已定位）

拦截页依赖 **Google reCAPTCHA** 做真人评估。本机网络到 Google / `gstatic` 不可达时，
reCAPTCHA 的 iframe 加载不出来、按钮一直是 disabled，**人也过不去**。所以：

> 这不是"手速/耐心"问题，也不是 cookie 问题，而是**网络出口**问题。

### 唯一有效解法：换非机房出口（墨西哥住宅 IP）

| 形态 | 结果 |
|---|---|
| 本机代理（FlClash 类客户端）+ Windows 系统代理 `127.0.0.1:7890`（HTTP/SOCKS5） | **有效**，出口实测 `189.253.199.238`（Mexico / AS8151 Uninet，住宅 IP），拦截消失 |
| 深圳移动热点 `120.229.72.208` | 无效（Google 超时，验证控件仍不渲染） |
| 境外机房代理 `188.253.121.26` | 无效（Google 可达，但商品页仍被拦） |

**公司电脑必须自带同样的住宅出口**——这是整个流程唯一的决定性变量。没有它，第一关就卡住，
后面所有脚本都白跑。

### 已实测无效、不要再走的路径

- 匿名 `curl`（换各种 cookie / UA 组合）→ 被重定向到 `gz/account-verification`
- 第三方抓取代理：`codetabs`（522）/ `allorigins`（502）/ `r.jina.ai`（不可达）
- 伪装爬虫 UA（Googlebot / Bingbot）→ 只返回壳页
- Wayback Machine 快照 → 数据陈旧且缺图
- 美客多备用 API：`api.mercadolibre.com/items`、`/products`、`/sites` → 401/403 需 token；`/p/MLM...` → 404
- 浏览器 `page.request.get` → IAB 通道报 `Storage.getCookies: Unsupported browser-level method without sessionId`

### 判据与动作

| 现象 | 性质 | 动作 |
|---|---|---|
| 返回验证码墙 / `gz/account-verification` | 出口被拦 | **换住宅出口**，然后**整批**重采；不要就地重试（会把整个会话标记） |
| 单批里 `blocked = "wall"` 数 ≥ 一半 | 出口已经开始被拦 | 立刻停，换出口，整批重采 |
| `blocked = "empty"`（有页面无数据） | 可能是壳页 | 先按上一条换出口再试；仍空则该 SKU 单独判下架 |

## 二、失效 SKU（美客多侧数据缺失，重试无意义）

| 现象 | 判定 | 动作 |
|---|---|---|
| 重定向到 `.../listado.../#redirectedFromVip=...`（类目浏览页），类目列表里检索不到该 item | 商品**已下架／删除** | **不重试**，记入清单「未采到」 |
| HTTP **404** | 商品已删除 | **不重试**，记入清单「未采到」 |
| 重定向到 `.../xxx/up/MLMUxxxx`（目录产品页），页面提示 `Este producto no está disponible` | 原 item 被卖家**停售**，同商品仍在 | 走**目录级采集**（`ml_catalog.py`），价格/卖家置 `null` |
| JSON-LD 里 `offers.price = 0` 且 `availability = OutOfStock` | 权威失效证据 | 同上，按实际落到目录级或记缺口 |

### 本轮已确认失效的具体 SKU（参考，重跑也不用再试）

| SKU | item | 现象 |
|---|---|---|
| `BKTLC50001` | `MLM-3553654912` | 重定向到类目浏览页，类目内检索 0 命中 → 已下架 |
| `00T0000000` | `MLM-2592045445` | 同上 |
| `AMU600000O` | `MLM-BRJN56669` | 链接 404 → 已删除 |

另有 2 个采成**目录级**（`BCU6000006` → `MLMU3773518725`、`BCTL000001` → `MLMU3828367202`）：
原 item 停售，同商品目录页仍在，采到标题/描述/属性/全部原图，价格与卖家不可得。

## 三、换电脑前先过的三道检查（公司电脑）

```bash
# 1) 出口：打开任一个美客多商品页，看是否出现安全验证页
#    （浏览器里人工看一眼最快；没出现即出口合格）
# 2) 浏览器通道
dumate-browser-cli --version
dumate-browser-cli init            # 失败时：dumate-browser-cli init --mode=extension
# 3) 飞书：在浏览器里打开多维表格，确认能看到行
```

三条都过再开始采；任一不过先解决它，不要带着问题开始抓。

## 四、附：`meli://` 深链弹窗（采集中会被系统弹窗打断）

美客多页面有时会拉起 `meli://` 自定义协议。本机没有注册处理器时，Windows 会弹出
「获取打开此 m 链接的应用」对话框，打断采集。两种处理：

1. **治标**：关掉那个拉深链的残留浏览器窗口（关掉就不再触发）
2. **治本**：注册一个空处理器 + 给 Edge 加白名单，让它静默放行

```
# 空处理器：HKCU\Software\Classes\meli
#   (默认) = "URL:meli Protocol (no-op handler)"
#   URL Protocol = ""
#   shell\open\command = wscript.exe //B //Nologo "<脚本>\noop.vbs" %1
#   noop.vbs 内容： WScript.Quit 0

# Edge 自动放行（REG_SZ，单行 JSON）：
#   HKCU\Software\Policies\Microsoft\Edge\AutoLaunchProtocolsFromOrigins
#   [{"protocol":"meli","allowed_origins":["https://mercadolibre.com.mx",
#     "https://*.mercadolibre.com.mx","https://mercadolibre.com","https://*.mercadolibre.com",
#     "mercadolibre.com.mx","mercadolibre.com"]}]
```

回滚：

```
reg delete "HKCU\Software\Classes\meli" /f
reg delete "HKCU\Software\Policies\Microsoft\Edge" /v AutoLaunchProtocolsFromOrigins /f
```

策略生效需要 Edge 里打开 `edge://policy` 点「重新加载策略」或重启浏览器（该策略支持动态刷新）。
格式要点：host **不带前缀点** = 匹配该域及全部子域；scheme 可省略。
